Building a web ingestion pipeline for RAG

Web pages are the largest open corpus available for retrieval-augmented generation, and also the messiest. Unlike a curated PDF corpus, every page brings its own markup, navigation chrome, cookie banners and paywall teasers. An ingestion pipeline exists to turn that mess into stable documents.

Stage 1 — Search

A search API such as Tavily turns a natural language query into a ranked list of URLs plus a snippet. The snippet is already useful: it tells you whether the result is worth downloading, and it can be stored as provenance metadata alongside the final document.

Stage 2 — Fetch

Downloading is where production pipelines quietly fail. You need timeouts, redirect following, a sane user agent, a size cap so a 200 MB video file does not land in your index, and content-type detection so you know whether you received HTML, a PDF or a binary blob.

Stage 3 — Parse

Parsing converts bytes into text. For HTML, a targeted extraction library will drop navigation and keep the article body. For PDFs you need layout-aware models: Docling and Unstructured both reconstruct reading order, section headings and table structure, which a naive text dump of the PDF loses entirely.

Stage 4 — Clean

Cleaning is mostly subtraction: normalize unicode, collapse wrapped lines, delete repeated menu items, remove boilerplate lines like cookie notices and copyright footers. Clean text is not cosmetic — boilerplate that survives into chunks becomes evidence the retriever can match, which is how answers end up quoting a footer.

Stage 5 — Chunk

Finally the document is split into retrieval units with a little overlap so a fact spanning a boundary is still findable. Every chunk keeps a pointer back to its URL and title, because provenance is what makes a RAG answer checkable.

Putting it together

The pipeline is a loop, not a one-shot job: search results that fail to fetch are dropped, pages whose parsed text falls below a length threshold are dropped, and the ones that survive are written as JSONL records ready for embedding. Measuring each stage separately — results per query, fetch success rate, chars before and after cleaning, chunk counts — is what tells you where quality is actually being lost.
